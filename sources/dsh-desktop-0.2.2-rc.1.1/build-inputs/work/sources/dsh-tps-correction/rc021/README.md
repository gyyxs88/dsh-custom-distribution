# Exact 0.2.1-rc.2 residual output-speed supplement

This directory is the maintained thin implementation. The parent 0.2.0-rc.2 source and artifacts remain rollback data and must not be activated on 0.2.1-rc.2.

Build with `node scripts/Build-Tps021.mjs <candidate-ready.json> <assigned-tps-output>`. It emits a deterministic profile bundle containing the independent `tpsCorrectionV2` projection and a replacement for only the public composer dock `activity` entry. The official `usage` entry is untouched. Activity keeps the official counts, durations, compact/detailed mode, anchored dialog and dismissal behavior. It reads the accepted `ui-chat.performanceUsage` preference and writes no settings. Both modes show one output-speed estimate, or 暂无法计算. The dialog describes the estimate as a route-specific weighted mean of eligible completed attempts.

The shared estimator calibrates received Unicode content against final outputTokens, excludes the first batch, TTFT and completion tail, and rejects burst-only, cancelled, missing-usage and unobserved-content samples. This is a receive estimate rather than server decode measurement; network buffering and content/token proportional allocation remain limitations.

Trajectory currently exposes no replaceable speed-detail slot. `scripts/Tps-Patch021.mjs` exports `patchTrajectory021(source)`: an exact SHA256 gate plus five unique replacements inject the same estimator, carry a metadata-only reading from the final attempt through the existing node/record, and replace its existing speed value/label. The builder emits its result only in an external `overlay/client.js`, along with the unchanged no-op official host entry and exact official client dependencies. Public Cordis bundle composition disables the built-in `ui-trajectory` loading entry by exact id/name and adds this one external source with the same package identity. The official ASAR is never written or repacked. Loading granularity is the entire generated client module; there is no maintained copy of trajectory source. Package identity and all other code stay byte-for-byte upstream except the five transformations. Installing this one bundle supplies both the activity and trajectory readings. Remove any previous TPS trajectory replacement first to avoid duplicate active package sources.

Retirement: remove the supplemental profile entry (including both inserted entries and its disable directive) once official code passes the same replay matrix and single-speed UI checks. The unchanged built-in trajectory entry then resumes loading directly from the original ASAR. Preserve historical source, artifacts and settings. Do not remove `sessionStats` or `tokenUsage`, recalculate billing, or edit original session logs.
